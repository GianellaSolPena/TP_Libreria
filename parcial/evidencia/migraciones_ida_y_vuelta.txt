Migraciones: ciclo ida y vuelta (alembic upgrade head -> downgrade base -> upgrade head)
=======================================================================================

Cómo se obtuvo (2026-11-06):
  - Base: contenedor descartable `docker run -d --rm --name libreria-f02 -e POSTGRES_USER=libreria
    -e POSTGRES_DB=libreria -e POSTGRES_PASSWORD=<aleatoria, no se versiona> -p 127.0.0.1:55432:5432 postgres:16-alpine`
    (PostgreSQL 16.15, la versión del stack), recién creada y vacía (`\dt` -> "Did not find any relations.").
  - Python 3.13.15 del venv de parcial/ (`.venv/Scripts/python.exe`).
  - Configuración por variables de entorno del proceso (POSTGRES_HOST=127.0.0.1, POSTGRES_PORT=55432, ...), sin tocar parcial/.env.
  - Comandos desde parcial/: `alembic upgrade head`, `alembic downgrade base`, `alembic upgrade head`; después de
    cada uno, el estado con psql vía `docker exec libreria-f02 psql -U libreria -d libreria -c "..."`.
  - La salida va cruda (stdout+stderr) con el código de salida de cada comando.

Resultado: los tres comandos terminan con código 0. Tras el downgrade queda sólo la tabla `alembic_version`
(sin filas) y la función `movimiento_stock_solo_agregado` ya no existe; el estado tras el segundo upgrade es
idéntico al del primero (15 tablas, versión 0004, función presente).
